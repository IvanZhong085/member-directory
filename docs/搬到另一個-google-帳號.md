# 把表單搬到另一個 Google 帳號

分會的東西掛在誰的個人帳號上，那個人離開時就會很麻煩。這份文件是把它搬到公用帳號的完整步驟。

**做完之後，舊帳號可以完全不參與名錄的運作。**

---

## 先看懂:哪些搬得動、哪些搬不動

| 東西 | 搬得動嗎 | 怎麼處理 |
|---|---|---|
| Google 表單 | ✅ | 轉移擁有權，**網址不變** |
| 回應試算表 | ✅ | 同上 |
| 名冊鏡像試算表 | ✅ | 同上 |
| **Apps Script 專案** | ❌ | 個人 Gmail 之間不能轉移，新帳號要自己建 |
| **觸發器** | ❌ | 觸發器屬於建立它的人、**以那個人的身分執行**，必須重建 |
| **指令碼屬性** | ❌ | 跟著專案走，新專案要重新填 |
| 已上傳的照片 | ⚠️ | 見下方「照片的坑」 |
| Cloudflare Worker | — | **完全不用動** |
| GitHub repo | — | 只有重建表單時才要改 `site-config.js` |

## 兩條路，先選一條

**A. 轉移擁有權**（表單網址不變，已收到的回應留著）
**B. 全部重建**（網址會變，`site-config.js` 要改，舊回應留在舊帳號）

> 如果目前 Drive 裡有**重複的表單**（`create*` 被跑過不只一次會這樣），先確認哪一份是活的：
> 開 Apps Script → 專案設定 → 指令碼屬性 → 看 `MEMBER_FORM_EDIT_URL` 指到哪個 ID，那份才是。
> 其餘的建議直接刪掉，連同它們的回應試算表與 `(File responses)` 資料夾。

---

## ⚠️ 照片的坑（兩條路都適用）

表單上傳的照片存在**表單擁有者**的 Drive。換帳號之後：

- **新的**上傳 → 進新帳號 ✅
- **舊的**照片 → 還在舊帳號，而新帳號的腳本是用自己的權杖去讀 → **可能讀不到**

所以：

> **搬家前，先把待認領區清空**（該認領的認領、不要的刪掉，然後發布）。

已經進名錄的照片不受影響——它們在發布時就已經變成 repo 裡的實體檔了，跟 Google 沒有關係。

---

## 路線 A：轉移擁有權

### A-1. 轉移 Drive 檔案（在舊帳號操作）

對這幾個檔案各做一次：

- 新夥伴資料填寫（表單）
- 新夥伴資料填寫(回應)（試算表）
- 來賓參訪報名（表單）
- 來賓報名(CRM)（試算表）
- 會員名錄・名冊鏡像（試算表，如果有建）

步驟：**右鍵 → 共用 → 加入新帳號為「編輯者」→ 再點新帳號旁邊的下拉 → 設為擁有者**

> `(File responses)` 資料夾會跟著表單走，不用另外處理。

### A-2. 建立新的 Apps Script 專案（在新帳號操作）

1. 開 <https://script.google.com> → 新增專案，命名為「新夥伴表單」
2. 把 `tools/google-form.gs` 的**全部內容**貼進去，儲存
3. 左邊齒輪「專案設定」→ 最下面「指令碼屬性」→ 新增三筆：

   | 名稱 | 值 |
   |---|---|
   | `RELAY_URL` | Cloudflare Worker 的網址 |
   | `INTAKE_SECRET` | **跟 Cloudflare 上那串完全一樣** |
   | `MEMBER_FORM_EDIT_URL` | 新夥伴表單的**編輯**網址（結尾是 `/edit`） |

   > `INTAKE_SECRET` 只存在 Cloudflare 與這裡，repo 裡沒有。找不到的話到 Cloudflare 重設一組新的，兩邊改成一樣即可。

4. 函式下拉選單選 `checkPhotoAccess` → 執行 → **跳授權時按允許**
   （這一步同時完成兩件事：拿到 Drive 權限、確認照片讀得到）
5. 執行 `setupNewMemberTrigger` → 重建送出觸發器
6. 執行 `checkNewMemberSetup` → 確認每一環都接上了

來賓表單同理，另開一個專案貼同一份程式碼，屬性只需要 `VISITOR_FORM_EDIT_URL`。

### A-3. 收尾（在舊帳號操作）

- 刪掉舊的 Apps Script 專案，或至少**把裡面的觸發器刪掉**
  → 不刪的話兩個帳號會同時收同一份表單，同一筆申請會進待認領區兩次
- 確認舊帳號在那些檔案上的權限降成「檢視者」或移除

### A-4. 驗收

填一筆測試表單（三個上傳題都放圖），然後：

- Apps Script 執行紀錄出現 `✅ 已送進待認領區`
- 後台待認領區看得到那筆，**而且有照片**
- 認領 → 發布 → 名錄上出現 → 再把測試資料刪掉

## 路線 B：全部重建

在新帳號做，舊帳號完全不動。

1. 開新的 Apps Script 專案，貼上 `tools/google-form.gs`
2. 指令碼屬性只填 `RELAY_URL` 與 `INTAKE_SECRET`（**不要**填 `MEMBER_FORM_EDIT_URL`）
3. 執行 `createNewMemberForm`
   - 它會建表單、回應試算表、掛好觸發器，並把編輯網址寫進指令碼屬性
   - 執行紀錄會印出「還要手動加三個上傳題」的指示
4. 照著指示到表單編輯頁，用滑鼠加三個「上傳檔案」題
   （Apps Script 沒有建立上傳題的方法，這是 Google 的限制）
5. 執行 `checkNewMemberForm` → 核對 13 題都對得上
6. 執行 `checkPhotoAccess` → 跳授權按允許
7. 執行 `createVisitorForm` 建來賓表單
8. **把新的表單網址貼回 `site-config.js`**：

   ```js
   MEMBER_FORM_URL: "…新夥伴表單的填寫網址…",
   VISITOR_FORM_URL: "…來賓表單的填寫網址…",
   ```

   改完發布網站。
9. 舊表單如果還在收件，記得停用或刪掉

> 如果新專案已經建過表單、你想重來一次：先執行 `forgetForms_()`。
> 它只會讓腳本忘記綁定，**不會刪 Drive 上的檔案**——刪除要你自己確認過再手動做。

## 常見問題

**Q：`INTAKE_SECRET` 要重新產一組嗎？**
不用。它是 Worker 與表單之間的密鑰，跟 Google 帳號無關。沿用原本那串最省事。

**Q：Cloudflare 要改嗎？**
不用。Worker 不知道也不在乎表單是誰的。

**Q：GitHub repo 要改嗎？**
路線 A 不用（網址沒變）。路線 B 要改 `site-config.js` 的兩個表單網址。

**Q：搬完之後舊帳號還需要保留嗎？**
名錄運作上不需要。但舊的回應試算表與舊照片還在那裡，確認不需要了再刪。

**Q：組長的後台帳號要改嗎？**
不用。那是 Cloudflare 的 `ADMIN_USERS`，跟 Google 完全無關。

**Q：新帳號要怎麼讓其他夥伴看到來賓／新夥伴的資料？**
把兩份回應試算表（`…來賓報名(CRM)`、`…新夥伴資料填寫(回應)`）移進一個資料夾，再分享那個資料夾即可 —— 檔案會繼承資料夾的權限，不必逐份設定。移動不會影響表單繼續寫入（連結綁的是檔案 ID，不是位置）。

⚠ 分享時把「一般存取權」設成**限制**、逐一加人；用連結分享的話權限至少要降成**檢視者**。裡面是來賓的電話與 LINE ID，設成「知道連結的任何人可以編輯」等於誰都能看、還能刪。

照片不在試算表裡，在 `(File responses)`。**不要搬那個資料夾**（位置綁在表單上），改用 `setPhotoArchiveFolder()` 讓腳本每次送出時自動歸檔到你指定的資料夾 —— 用法見 README「新夥伴照片自動歸檔」。
