# 會員名錄網站

純靜態的一頁式會員名錄（白底紅襯色）。公開名錄是**唯讀**的；只有持有**管理帳號密碼**的人能進入編輯模式、發布更新。GitHub 權杖本人放在一個小型雲端中介服務（Cloudflare Worker）裡，**從頭到尾不會出現在任何瀏覽器裡**——登入後由伺服器代為發布，任何人（含小朋友）在任何電腦，只要帳密對就能編輯；可以開多組帳號給不同的人用。

## 一、部署到 GitHub Pages（設定一次）

1. 在 GitHub 建立一個**新的公開 repo**（例如 `member-directory`）。
2. 把 **`member-site/` 裡面的所有檔案**放到這個 repo 的**根目錄**（讓 `index.html` 在最上層），推上去。
3. repo → **Settings → Pages** → Source 選 **Deploy from a branch** → Branch 選 `main`、資料夾 `/(root)` → Save。
4. 等一下，網站會出現在 `https://<你的帳號>.github.io/<repo 名稱>/`。把這個網址存成書籤。

> 建議用「新的、獨立的公開 repo」，不要和其他專案混在一起。

## 二、開啟一鍵發布（設定一次，由大人做）

這一步做完後，之後任何人只要輸入**自己的帳號密碼**就能編輯並發布，完全不用碰 GitHub 權杖、檔案或 Git 指令。這一步分兩段：先建 GitHub 權杖，再照 **`worker/README.md`** 的教學把它交給一個免費的 Cloudflare Worker 保管。

1. 到 GitHub → 右上頭像 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**。
2. 設定：
   - **Repository access** 選「Only select repositories」→ 只勾**這個名錄的 repo**。
   - **Permissions → Repository permissions → Contents** 設為 **Read and write**。
   - 其他不用動，建立後**複製權杖**（只會顯示一次）。
3. 打開 **`worker/README.md`**，跟著步驟在 Cloudflare（免費帳號即可）建立一個 Worker，把上面的權杖、以及一份**管理帳號密碼表**貼進去（過程都在網頁上點一點，不需要安裝任何軟體）。
4. 拿到 Worker 網址後，打開名錄網站 → 點右下角**小齒輪** → 「連線設定」→ 貼上網址 → 儲存。

完成後，**GitHub 權杖只存在 Cloudflare 那一端**，任何瀏覽器都不會保管它；操作者只需要知道自己的帳號與密碼。

> ⚠️ 帳號密碼等於編輯權限，不要隨便公開；密碼錯太多次（15 分鐘內 5 次）會自動暫時鎖住，防止亂猜。要新增／刪除帳號、換密碼、換權杖，都在 Cloudflare 的 Worker 設定裡改（見 `worker/README.md` 的「管理帳號」一節），不用改網站程式碼。
>
> 每次發布會把**發布者的帳號**記進 GitHub 的提交紀錄，例如「更新會員名錄（a1・A1）」，事後可以追查是誰改的。

### 兩種角色

| 角色 | 看得到 | 能做 |
|---|---|---|
| **總管理員** | 全會 12 組 | 全部功能（含連線設定、增刪分組、編輯任何人） |
| **組長** | 只有自己那一組 | 編輯本組成員與照片、改組長姓名與招募席位、匯出 CSV、下載備份、缺資料清單、發布 |

帳號綁定的是**組別代號**（A1、B2…）而非姓名，組長換人時只要改密碼與備註，帳號不用動。

> ✅ **這是伺服器端的真實權限**：資料按分組拆成 `data/<代號>.json`，Worker 只允許組長寫自己那一個檔案。就算改前端、開開發者工具，送出別組的檔案一樣會被拒絕（`forbidden_path`）。
>
> 多人同時編輯還有**版本落後偵測**：若別人在你編輯期間發布過同一組，你這次發布會被擋下並提示重新整理，避免蓋掉對方的修改。不同組之間互不影響，可以同時編輯發布。

## 三、日常怎麼更新（小朋友也會）

1. 打開名錄網站，點右下角**小齒輪** → 輸入**你的帳號與密碼**進入編輯模式。
2. 修改：
   - **加人**：上面輸入框打姓名，按 Enter 就新增一位（可連續加）。
   - **刪人／刪組**：成員卡的刪除鈕、左邊分組滑過的 ✕；刪錯了右下角按「**復原**」就回來。
   - **換照片**：成員卡「更換照片」選圖，會自動縮圖，不用另外處理圖片。
   - **複製**：資料相似的人可用「複製」鈕。
3. 改好後，按右上角紅色「**發布到網站**」。
4. 等大約 1 分鐘，公開網站就更新好了 ✔

> 「下載備份」按鈕會存一份 `data.js` 到電腦，當備份用（平常用不到）。密碼登入後**每 30 分鐘**需重新輸入一次密碼（固定期限，非閒置計時）；若在編輯到一半時到期，畫面會提示重新登入，**草稿資料不會遺失**，登入後再按一次「發布」即可。


### 舊草稿不會再蓋掉別人的修改

後台會把還沒發布的修改存在**這台電腦的瀏覽器**裡（草稿），下次打開同一台電腦會接著用。以前的問題是：一份放了很久的草稿，發布時會把整組換成草稿裡的舊內容 —— 2026/10/1 就是這樣，一份 8 月的草稿把 9 月才加入的夥伴刪掉、把已經刪掉的人加回來、把別人補的資料清空。

現在打開後台時，如果草稿是在網站更新**之前**存的，系統會**只把你真的改過的地方**套到最新的資料上：

- 你沒碰過的夥伴，一律用網站上最新的內容；你新增、刪除、修改的夥伴才會用你的版本。
- 同一位夥伴的同一格，你和網站上都改過 → 保留網站上的版本，畫面上會列出來請你確認。
- 畫面上會出現一段說明（要按「知道了」才會收起）：草稿是哪一天存的、套用了哪幾處、哪幾處保留網站上的版本。
- 草稿太舊、沒辦法判斷你改了什麼時，**發布會被擋下**，請照畫面說明：「下載備份」→「捨棄變更」→ 重新修改。不會再有「繼續 = 覆蓋」這個選項。

### 刪錯人可以自己救回

每次發布刪掉的夥伴，會自動收進**私有的回收區**（Cloudflare R2，不公開），連同他所有的資料：

1. 後台總覽儀表板 →「🗑 最近刪除的夥伴」→「查看」。
2. 找到那位夥伴 → 按「**救回**」→ 確定。他會回到原本那一組、原本的位置，照片也都還在，幾分鐘後前台就會看到。
   - 手上有還沒發布的修改時要先發布（或捨棄變更）才能救回。
   - 組長只看得到、救得回自己那組的人；總管理員看得到全部，另外可以「永久刪除」確定不要的。
3. 建議在 Cloudflare R2 加一條 `recycle/`、90 天的自動清除規則（見 `worker/README.md`），超過 90 天的回收紀錄會自動清掉。

回收區是從這一版開始才有的；這之前刪掉的人不在裡面，要救回的話請找網管從 GitHub 的歷史紀錄還原（每一次發布都留在歷史紀錄裡，不會真的消失）。

## 四、分享夥伴與聚光燈產生器

### 每位成員都是一張數位名片

成員內頁下方有「**分享這位夥伴**」工具列：

- **複製連結**：複製這位成員的專屬網址（`…/m/成員id.html`）。貼到 LINE／FB 會顯示**本人照片與介紹**的預覽卡。
- **QR code**：現場給人掃，直接開啟該成員介紹頁（跨會拜訪、擺攤、名片背面都好用）。
- **存入通訊錄**：下載 vCard（.vcf），一鍵把姓名、行業、服務摘要與介紹連結存進手機聯絡人。
- **貼文／分享卡**：跳到聚光燈產生器並自動帶入這位成員。
- 手機瀏覽器另有系統原生「分享…」按鈕。

### 聚光燈產生器（spotlight.html）

網站管理員的每週發文工作台：選一位夥伴，立刻得到——

1. **三種貼文文案**：FB／IG 版、正式版、LINE 短版（模板直接可用；發文前請過目）。
2. **AI 潤飾提示詞**：一鍵複製整包夥伴資料＋寫作要求，貼給 ChatGPT／Claude 產出更活的版本，AI 不會拿到資料以外的內容。
3. **分享卡圖片**：白底紅襯設計、含照片／標語／服務／引薦對象／QR code，直式 4:5 與方形 1:1 兩種尺寸，PNG 下載即可發文。

每週輪播就按「下一位 →」，順序照名錄分組排列。

### 分享預覽頁（m/ 資料夾）

`m/成員id.html` 是給 LINE／FB 爬蟲看的小頁面（og 標籤），真人開啟會自動跳轉回名錄內頁。**名錄有增刪成員後**，在 repo 根目錄執行：

```
node tools/build-member-pages.mjs
```

會重新產生全部成員頁並清除失效頁，跟著一起發布即可。只改姓名以外的資料（服務、照片等）不重跑也能用，但預覽文字會是舊的，建議順手重跑。

## 五、名冊管理：CSV 匯出入

後台工具列有三顆按鈕，給「常常要核對人數、調整分組」的網管用：

### 匯出 CSV

一鍵下載全會名冊（Excel 直接開，中文正常）。欄位：編號、姓名、行業職稱、分組代號、分組名稱、服務項目、適合引薦對象、我有、我要、宣傳標語、所屬公司、主要營業項目、公司網站、照片、名片、商品照片數、最後更新、資料需確認、刪除。多項欄位（服務、我有、我要等）以 `|` 分隔。

### 沒有「匯入」功能

2026/7 起本站**不提供任何批次匯入管道**（CSV 匯入、PPT 匯入、Google 表單回應皆已移除）。成員資料一律在後台逐欄編輯——資料按分組拆開由各組組長自行維護後，一次要動整份名錄的批次工具反而是風險來源（一張錯表就能毀掉全會資料）。

「匯出 CSV」保留，用途是核對與製表，不再是「改完再灌回去」的往返流程。

> ℹ️ **照片儲存**：每次發布後，GitHub Action 會在一兩分鐘內自動把內嵌照片轉成 `images/` 實體圖檔、重建 `m/` 分享預覽頁（見下一節）。Worker 升級（見 `worker/README.md` 的「升級」一節）可以讓**照片實體檔**在發布當下就完成，屬於選配加速；分享預覽頁一律由 Action 重建（唯一產生器是 `tools/build-member-pages.mjs`，後台不重生）。

## 六、Google 試算表每日同步（roster.csv）

網站每次發布後，GitHub Action 會自動做三件事：**內嵌照片轉實體檔、重建分享預覽頁、更新名冊鏡像 `roster.csv`**。名冊鏡像的固定網址：

```
https://ivanzhong085.github.io/member-directory/roster.csv
```

### 接到 Google 試算表（設定一次，約一分鐘）

1. 開一個新的 Google 試算表。
2. 在 `A1` 貼上：`=IMPORTDATA("https://ivanzhong085.github.io/member-directory/roster.csv")`
3. 完成。之後名錄一有發布，試算表會**自動跟上**（Google 約每小時重抓一次，至少每日更新）。

用途：核對人數與分組、製作**分會產業小組 PDF**（可另開分頁用 `FILTER`／樞紐整理版面後「檔案 → 下載 → PDF」）、給幹部唯讀名冊。

### 注意

- 試算表是**唯讀鏡像**——在上面改字不會改到網站，本站也沒有匯入功能。要改資料請到後台編輯。
- `roster.csv` 不含 BOM（Google 取向）；要用 **Excel** 開名冊請改用後台的「匯出 CSV」（含 BOM，中文不亂碼）。
- 名錄增刪成員後**不再需要**手動跑 `node tools/build-member-pages.mjs`，Action 會自動處理；本機開發時仍可手動執行。

## 七、來賓參訪報名表單（Google 表單）

來賓在 `visitor.html` 按「我要報名參訪」後填的表單，回應會進一份獨立試算表當作**來賓 CRM**。表單只有五題：**姓名、電話、LINE ID、職業必填，引薦人姓名選填**（沒有引薦人、自己找上門的來賓也收得到）。

### 建立步驟（約 3 分鐘，做一次）

1. 開 [script.google.com](https://script.google.com) → **新增專案**，把 `tools/google-form.gs` 整個檔案內容貼進去、儲存。
2. 上方函式下拉選單選 **`createVisitorForm`** → 按 **執行**。第一次會跳授權：選帳號 →「進階」→「前往（不安全）」→「允許」。
3. 看下方**執行紀錄**，會印出三個網址；把**第 ① 個**（給來賓填的網址）貼進 `site-config.js` 的 `VISITOR_FORM_URL`。
4. 發布網站。來賓頁的「我要報名參訪」按鈕就會直接開表單，後台總覽儀表板也會出現「來賓報名表單」捷徑。

第 ② 個網址是報名回應試算表（你的來賓 CRM，建議手動加「追蹤狀態／到訪日／結果」三欄），第 ③ 個是表單編輯網址，之後要改題目從那裡進。

> ⚠️ **不要重複執行 `createVisitorForm`**，每跑一次就多建一份新表單。要改題目請到表單編輯頁改。

> 註：已上架的夥伴要更新資料，見「八、夥伴資料更新表單」；新夥伴用新夥伴表單。

### 來賓在名錄裡看得到什麼

下面這些都是前台自己長出來的，後台不用多做設定；席次的資料來源就是後台各組的「招募席位」欄。

- **招募席次全部公開。** 後台「招募席位」填了什麼，前台四個地方都看得到：群組頁上方的「這組還在找這些專業的夥伴」橫幅（超過 6 席先收起，按「還有 N 席」才展開）、首頁組卡的「招募中 N 席」、來賓頁 12 組小卡（最多列 3 席，其餘寫「等 N 席」），以及搜尋結果的「招募中的席次」（打兩個字以上才會比對席次，免得一個「師」字命中所有席次）。空白列與重複的席次會自動略過，不必特別清。
- **名錄左側分組列的最後一格常駐「來賓參訪」入口**，直通 `visitor.html`；群組頁、成員頁也各有一顆報名按鈕。這些按鈕會在網址後面帶脈絡：群組頁帶 `visitor.html?g=組id`、成員頁帶 `?m=成員id`、搜尋沒有結果時帶 `?q=關鍵字`（搜尋結果裡的席次卡片會同時帶 `?g` 與 `?q`）。
- **來賓頁收到 `?m`／`?g`／`?q` 只會顯示、不會送出。** 來賓頁讀到這些參數，只在「報名參訪」標題下多一句「你想認識的是 ○○○ —— 報名後接待夥伴會幫你安排」之類的脈絡；**不會送進 Google 表單**（表單目前沒有對應欄位），所以來賓 CRM 裡看不到他想認識誰，接待夥伴用 LINE 聯繫時要自己問。id 對不上（例如夥伴已離會）就當沒這回事，不會報錯。
- **送出成功後的「接下來會發生什麼」與「加入行事曆」。** 例會時間、地點寫在 `visitor.html` 最上面的 `VISITOR.meetTime`／`meetPlace`；「加入行事曆」排的是「下一個週四 06:30–09:00」，這組數字寫在同一個檔案的 `nextThursday()`（開始 06:30，以及「週四過了 09:00 就算下週」的判斷）與同檔稍後 `showNextSteps()` 開頭的結束時間 09:00（在檔案裡搜尋這兩個名字就找得到）。**改例會時間時這幾處要一起改**，不然頁面寫一個時間、行事曆卻排另一個。

### 有人報名時寄信到分會信箱（建議設定）

來賓送出報名後，資料只會靜靜多一列在來賓 CRM 試算表裡，沒有人會每天去開那張表。裝一個「表單送出」觸發器，每收到一筆就寄一封信到分會信箱：信裡有姓名、電話、LINE ID、職業、引薦人與試算表連結，接待夥伴看信就能直接用 LINE 聯繫。

做法（做一次，約 1 分鐘）：

1. 把最新的 `tools/google-form.gs` 整份貼進 Apps Script 專案、儲存。
2. 函式下拉選單選 **`setupVisitorNotify`** → 執行。它會裝好觸發器、印出收件人與授權狀態、並寄一封測試信到分會信箱。
3. 執行紀錄若出現紅字「需要重新授權」，用瀏覽器打開它印出的網址完成同意，再跑一次。
4. 收到測試信就完成了。之後想確認觸發器還在不在，跑 `checkVisitorNotify`。

收件人依序找第一個有設的：`VISITOR_NOTIFY_EMAIL` → `NOTIFY_EMAIL` → `ALERT_EMAIL` → 腳本擁有者。分會信箱已經設在 `ALERT_EMAIL` 的話什麼都不用多做；要另外寄到接待組的信箱就跑 `setVisitorNotifyEmail("接待組信箱")`（要帶參數，不能直接從下拉選單選它按執行，做法見「八」的「要帶參數的函式怎麼執行」）。

> ⚠ 這封信含來賓的電話與 LINE ID，請不要在分會信箱設定自動轉寄到群組。

## 八、夥伴資料更新表單（已上架的夥伴自己更新資料）

已經在名錄上的夥伴，用這份 Google 表單**選自己的名字**，補上或修改公司、主要營業項目、我有／我要等文字資料。不用登入 Google，手機從 LINE 點進來約 2 分鐘填完。

```
夥伴填表單 → 進「待審核」（私有，不公開）→ 組長在後台逐欄確認、按「套用」→ 幾分鐘後前台就更新
```

- 送出的內容**不會直接上線**，先存在 Cloudflare R2 的私有空間（和待認領照片同一個 bucket，放在 `updates/` 底下），等那一組的組長或總管理員在後台確認。
- 按「套用」是伺服器端直接寫進網站，**不必再按「發布到網站」**。
- 只收文字。要換形象照、補名片或商品照，請夥伴直接用 LINE 傳給組長，由組長在成員卡上傳。
- 還沒上架名錄的新夥伴不是用這份，是用新夥伴表單（送出後進待認領區）。

### 為什麼要先審核

表單不必登入，只靠「選自己的名字」辨識身分 —— **任何拿到網址的人都能選別人的名字**。所以每一筆都要由組長看過才上線，審核畫面也會固定提醒「表單不會驗證是不是本人」。另外：

- 表單網址只出現在 LINE 群和後台，**公開名錄上沒有任何入口**。
- 沒審核過的內容（包括冒名送件和給組長的私人備註）只放在私有空間，不進公開的 GitHub repo —— 一旦進了 git 歷史就刪不掉，還會掛在真實會員的名下。

### 為什麼不收照片

Google 表單只要有「上傳檔案」題，整份表單就會**強制登入 Google 帳號**。LINE 內建的瀏覽器擋 Google 登入，從 LINE 點進來的夥伴多半會卡在登入畫面，沒有 Google 帳號的 iPhone 使用者更是完全送不出去。所以這份表單只收文字，LINE 點了就能填；照片維持「LINE 傳給組長 → 組長在後台上傳」。

> ⚠ 不要自己在表單上加「上傳檔案」題，也不要打開「收集電子郵件」或「限制只能回覆 1 次」（被灌單時也別用它擋重複送件，照下面「被灌單怎麼辦」處理）—— 這三種都會讓整份表單要求登入。`checkMemberUpdateForm` 看到這三種情況會印 ✗。

### 入口在哪裡、怎麼給夥伴連結

入口**只在後台**，前台完全不放：

| 入口 | 誰會用到 | 給出去的連結 |
|---|---|---|
| 總覽儀表板「✏️ 夥伴資料更新表單」 | 登入後台的人 | **通用連結**：夥伴自己在選單裡找名字 |
| 「缺資料清單」的催收訊息 | 總管理員（看全分會） | 附一條通用連結 |
| 同上 | 組長（只看自己那組） | 每一位後面附**只預選名字**的連結（不帶資料）；整段超過 4,800 字就退回只附通用連結 |
| 成員卡「🔗 複製已帶好名字的更新連結」 | 能編輯那一組的人 | **已帶好名字的連結**：名字已經選好，還把他目前的文字資料預填進去，夥伴看著舊內容改就好 |

- 已帶好名字的連結**不是密碼**：任何人拿到都能用他的名字送出，而且網址裡帶著他目前的資料。**只私訊給本人，不要貼到群組。**
- 這條連結的最後一題「**連結代碼**」會自動帶入一串英數字，記的是「產生連結的當下，每一格帶入了什麼」。系統靠它分辨哪些格子是連結帶進去、本人沒動過的，直接略過 —— 夥伴從 LINE 聊天紀錄點同一條舊連結再填一次，也不會把後來的修改改回去。**不用管它**；夥伴把它刪掉也照樣送得出去，只是舊連結再填一次時少一層保護。

### 審核畫面怎麼看

後台待認領區下方的「✏️ 夥伴資料更新（待審核）」。組長只看得到自己那組，總管理員看得到全部，唯讀帳號整塊看不到。

- **每位夥伴一張卡**。同一位有好幾筆時，依「夥伴按送出的時間」由舊到新，一次只能處理最舊的那一筆。
- 按「查看」展開：最上面是填寫時間、這位夥伴頁面最後更新的時間、要特別注意的警示；有「給組長的備註」會醒目放在最上面。
- **差異表**：欄位｜目前（網站上）｜更新後｜怎麼套用。文字欄位是一個勾選框；清單欄位（服務項目、適合引薦對象、我有、我要、Slogan）三選一：**整格換成新的／加在原本後面／不套用**，並逐項標出保留、會刪掉、新增。
- **以下情況預設不勾**，要你看過再決定：
  - 和網站上目前一樣（不用套用）；
  - 整筆有標頭警示：系統把這筆改送到別組、名字和連結代碼對不上、補送進來而且比網站資料舊；
  - 內容太長被截斷；連結發出之後，網站上這一欄已經改過；後面還有一筆較新的也改了這一欄；
  - **網站出現新網址（包括原本空白）**—— 網址會直接放上公開名錄，請先跟本人確認是他的網站；
  - **原本有內容的「行業／職稱」被改** —— 選錯名字時最常被換掉的就是這一行；
  - 清單欄位裡沒有任何一項是原本的 —— 夥伴可能只寫了要新增的，請改選「加在原本後面」。
- **資料需確認**：這位夥伴被標「資料需確認」時，會多一個勾選框「我已經跟本人確認過（同時取消前台的「資料需確認」提示）」，**預設不勾**（表單不驗證本人，不能讓一筆沒驗證的送件自動取消提示）。被標的夥伴什麼都沒改就送出，也會出現一張「**本人確認資料正確**」的卡：跟本人確認過之後，勾這一格再按套用，就能取消提示。
- 三顆按鈕：
  - **✅ 套用勾選的更新**：直接寫進網站。手上還有沒發布的修改時，要先發布（或捨棄變更）才能套用。
  - **✔ 已處理（我已手動改好）**：只把這筆從清單移除，網站不動。備註裡的要求（刪掉某一格、改名、換組）要你手動到成員卡改，改完按這顆。
  - **✖ 不採用**：刪掉這筆，網站不動；可以複製一段訊息給本人（填的原因只放進剪貼簿，不存檔）。
- **名錄上找不到這位夥伴**（被刪除或換組）：不畫差異表，改成唯讀列出他送來的內容。按「📋 複製內容」轉抄到他現在的成員卡（系統會幫你找名錄上有沒有同名的人），發布後再按「已處理」。
- 套用時，系統會逐欄比對「你畫面上看到的目前值」和網站上真正的值；中間被別人改過就停下來請你重新確認，不會蓋掉別人剛改好的內容。萬一畫面說「不確定有沒有寫進網站」，照畫面的說明按「重新整理」判斷就好 —— 再按一次套用也不會重複寫入。

### 上限

| 項目 | 上限 | 超過時 |
|---|---|---|
| 全分會待審核 | 100 筆 | 夥伴送出的更新會被退回。後台在 80 筆時就會提醒 |
| 每位夥伴 | 3 筆 | 這位夥伴新送的會被退回，系統寄信請組長先處理他的待審核 |
| 每小時送件 | 60 筆 | 表單自動暫停收件，並寄信到 ALERT_EMAIL（見下面「被灌單怎麼辦」）。全分會才 90 人，正常不會碰到 |
| 保存期限 | 建議 90 天 | 在 R2 加一條 `updates/`、90 天的規則（部署表第 1 步）：超過 90 天沒人審的更新自動作廢，請夥伴重送 |

同一筆重送、或同一位夥伴內容完全相同的送件，只會算一筆。最舊的一筆等了 7 天以上，後台的提醒會升級成警示。

### 會寄哪些信

| 什麼時候 | 寄給 | 頻率 |
|---|---|---|
| 有夥伴送來更新 | NOTIFY_EMAIL（沒設就不寄） | 6 小時最多一封，內容是「目前共 N 筆待審核」 |
| 有人選了「找不到我的名字」 | NOTIFY_EMAIL，沒設就寄 ALERT_EMAIL | 6 小時彙整一封，只列出過濾後的姓名 |
| 某位夥伴的送件沒進後台（找不到人、已經有 3 筆…） | NOTIFY_EMAIL，沒設就寄 ALERT_EMAIL | 同一位、同一個原因每天最多一封 |
| 系統出錯（Worker 沒升級、密碼不一致、網站讀不到…） | ALERT_EMAIL | 同一個錯誤每小時一封 |
| 表單自動暫停收件 | ALERT_EMAIL | 暫停時一封 |
| 名字選單超過一天沒同步成功 | ALERT_EMAIL | 每天最多一封 |

信裡只有過濾後的「代號・姓名」、錯誤碼與回應 ID，**不放夥伴寫的內容和備註**。一般 Gmail 帳號每天只能寄給 100 位收件人，而且和新夥伴申請、來賓報名通知共用；今天剩不到 20 封時，只寄系統出錯的通知。

### 部署步驟（做一次；每一步的檢查點沒過就先停下來）

| # | 動作 | 檢查點 |
|---|---|---|
| 1 | Cloudflare → R2 → bucket → Settings → Object lifecycle rules：確認每一條規則的 Prefix 都是 `pending/`（建議再加一條 `updates/`、90 天） | 沒有任何一條是空白 prefix 或套用整個 bucket 的規則 |
| 2 | 部署新版 Worker（`worker/publish-relay.js`，見 `worker/README.md` 的「升級到夥伴資料更新表單」） | 打 `/ping`：`caps.memberUpdate` 是 `true`（`false` 就停下，先綁 R2），而且 `memberUpdateSite` 等於網站網址（不同就在 Cloudflare 加一個變數 `SITE_BASE`） |
| 3 | 把新版 `tools/google-form.gs` 貼進**新夥伴表單那個 Apps Script 專案**（要用同一組 `RELAY_URL` 和 `INTAKE_SECRET`）→ 執行 `checkNotifySetup` | 「授權狀態」是 ✅ |
| 4 | 執行 `createMemberUpdateForm` | 執行紀錄印出表單網址；用手機的無痕視窗打開，看得到題目，沒有出現「要求存取權」或「請登入」 |
| 5 | 執行 `checkMemberUpdateForm` | 除了 site-config 那一行之外全部 ✅ |
| 6 | 從手機 LINE 點表單網址，用自己的名字送一筆**只改「公司網站」**的測試 | 不用登入就能送出；NOTIFY_EMAIL 收到通知；後台出現這一筆，網站那一列預設不勾 → 按「不採用」 |
| 7 | 到 GitHub 網頁版打開 `site-config.js` → 按鉛筆 → 貼上 `UPDATE_FORM_URL` 和 `UPDATE_FORM_ENTRIES` 兩行 → Commit changes（**後台的「發布」改不到這個檔**：Worker 只允許寫 `data/` 和 `images/`） | 約 10 分鐘內，後台總覽儀表板出現「✏️ 夥伴資料更新表單」，成員卡出現「複製已帶好名字的更新連結」 |
| 8 | 在自己的成員卡按「複製已帶好名字的更新連結」，用手機打開，只改一格送出；再用**同一條連結**送一次，這次什麼都不改 | 第一次後台出現一筆，只有改的那一格；第二次不會多一筆（Apps Script 執行紀錄是「內容和名錄上一樣，沒有建立待審核」）。最後把那一筆按「不採用」 |
| 9 | 再跑一次 `checkMemberUpdateForm` | **全部 ✅ 才把網址發到 LINE** |

- 第 2 步的 `/ping` 要用 **POST** 打：Worker 只收 POST，用瀏覽器直接開網址會看到 `method_not_allowed`，那是正常的。可以在終端機執行 `curl -s -X POST https://你的Worker網址/ping`（Windows 請打 `curl.exe`：PowerShell 裡的 `curl` 是另一個指令）；第 5 步 `checkMemberUpdateForm` 的「Worker」那一行也會再核對一次這兩項。
- 第 7 步要貼的兩行，在第 4 步執行紀錄的第 ⑥ 段；找不到了就執行 `printMemberUpdateLinkConfig` 重印。
- 函式都是在 Apps Script 上方的函式下拉選單選好再按「執行」；括號裡要帶東西的（例如下面的補送），照下一段做。

**要帶參數的函式怎麼執行**

「執行」按鈕沒辦法帶參數。`resendMemberUpdate("回應 ID")`、`dismissFailedMemberUpdate("回應 ID")`、`forgetMemberUpdateForm(true)`、`setAlertEmail("…")` 這類括號裡有東西的函式，直接從下拉選單選它按執行，只會看到用法錯誤、「清單上沒有這筆」或被擋下來；`setAlertEmail`、`setNotifyEmail`、`setVisitorNotifyEmail` 沒帶參數還會**把原本設好的信箱清掉**。要另外包一層：

1. 左邊「檔案」旁的 ＋ →「指令碼」→ 檔名打 `暫用` → 按 Enter。已經有「暫用」這個檔，就直接點開它，**不要再開第二個**。
2. 把「暫用」裡的內容**整個換成**下面這一行，大括號裡換成這次要跑的那一句：

   ```js
   function runOnce() { resendMemberUpdate("貼上回應 ID", "A1・正確姓名"); }
   ```

   其他例子：`function runOnce() { dismissFailedMemberUpdate("貼上回應 ID"); }`、`function runOnce() { forgetMemberUpdateForm(true); }`、`function runOnce() { setAlertEmail("yourname@gmail.com"); }`。引號要用英文半形的 `"`，不能是「」或全形的 ＂。
3. 按存檔（磁碟圖示）。跳出錯誤訊息（例如 `Syntax error`）代表貼錯了，檢查引號和括號，先不要往下做。
4. 上方函式下拉選單選 `runOnce` → 按「執行」→ 看下方的執行紀錄。
5. 用完**把「暫用」這個檔刪掉**（滑到檔名上 → 旁邊的 ⋮ →「刪除」）。留著的話，日後誤選 `runOnce` 會把同一件事再做一次。

主程式那個檔（通常叫「程式碼.gs」，就是貼 `google-form.gs` 的那個）不要動：在裡面加減程式碼容易誤刪到別的地方，下次整份貼新版時也會被蓋掉。

### 常見問題

**夥伴說找不到自己的名字**
- 選單依組別排列，他可能在別的組；選單**每小時**跟名錄同步一次，剛上架或剛改名的要等一下。
- 最省事的做法：組長在後台他的成員卡按「複製已帶好名字的更新連結」私訊給他，名字已經選好。
- 選單最後一個選項是「找不到我的名字」，選了會請他留下姓名，系統每 6 小時最多寄一封彙整信。請組長跟信裡的人聯絡；他們想更新的內容在表單的回應試算表裡。
- 同一組有兩位同名的夥伴時，選單只能列一位，系統會寄信提醒。請在後台把其中一位的姓名加註區別（例如加上公司簡稱）。

**送出之後沒反應**
- 名錄沒變是正常的：要等組長在後台按「套用」才會上線（表單送出後的確認訊息也是這樣跟夥伴說的）。
- 後台的待審核清單裡沒有這一筆：代表從 Apps Script 送到 Worker 的途中失敗了。資料一定還在表單的回應試算表裡；失敗時系統會寄信（錯誤原因與回應 ID 都在信裡），執行 `checkMemberUpdateForm` 也看得到「可自動補送」「需人工處理」各幾筆。修好後照下一題補送。
- 總管理員登入後台看到橫幅「夥伴資料更新表單已經公開，但發布服務還沒升級或還沒接上 R2」：Worker 還沒更新或沒綁 R2，夥伴送出的更新會全部被退回，回到部署表第 2 步。
- 夥伴看到「暫停收件中」：表單被自動暫停了，見下面「被灌單怎麼辦」。

**送失敗的怎麼補送**

修好原因之後，在 Apps Script 執行（第一行沒有參數，下拉選單直接選；後兩行要帶參數，照上面「要帶參數的函式怎麼執行」包一層）：

```js
resendFailedMemberUpdates()                      // 一次補送所有「可自動補送」的
resendMemberUpdate("回應 ID", "A1・正確姓名")     // 指定正確的名字補送一筆（夥伴改過名、選錯人）
dismissFailedMemberUpdate("回應 ID")              // 已經手動處理好、或確定是垃圾單的，移出補送清單
```

- `resendFailedMemberUpdates` **只補送「可自動補送」的**（系統暫時出錯、設定還沒弄好、待審核滿了之類）。
- 「需人工處理」的（名錄上找不到這位、同組同名、內容太長、選項格式不對、暫停收件那一刻進來的）不會自動補送 —— 原封不動再送一次只會再失敗一次。執行 `checkMemberUpdateForm`，「需人工處理」那一行會逐筆列出回應 ID、錯誤碼與建議做法，照著用 `resendMemberUpdate("回應 ID", "A1・正確姓名")` 或 `dismissFailedMemberUpdate("回應 ID")` 處理。
- 也可以請組長 LINE 本人重新填一次，和補送擇一即可（內容相同的不會重複建立）。

**選單多久更新一次**

每小時自動跟公開名錄同步一次（`syncMemberUpdateNames`）。後台發布之後前台要幾分鐘才更新，再等下一次同步，所以剛新增或改名的夥伴最多要等一個多小時。急的話在 Apps Script 手動執行 `syncMemberUpdateNames`。連續超過一天沒同步成功，會寄信到 ALERT_EMAIL。

**被灌單怎麼辦**

表單 1 小時內收到超過 60 筆，會**自動暫停收件**（填表的人會看到「暫停收件中」），並寄一封信到 ALERT_EMAIL。照這個順序處理：

1. 總管理員到後台「夥伴資料更新（待審核）」，勾選不是夥伴本人送的卡片，按「不採用勾選的更新」一次清掉（一次最多 100 筆）。
2. 確認沒問題之後，打開表單編輯頁 →「回覆」分頁 → 打開「接受回覆」。
3. 在 Apps Script 執行 `checkMemberUpdateForm`，處理「需人工處理」裡錯誤碼是 `flood_paused` 的（暫停那一刻進來的送件）：確定是夥伴送的，執行 `resendMemberUpdate("回應 ID")`；其他的執行 `dismissFailedMemberUpdate("回應 ID")`（這兩個都要帶參數，做法見上面「要帶參數的函式怎麼執行」）。

重新打開之後**又反覆被灌單**，代表表單網址已經流到 LINE 群以外，要換一份新表單：

1. 執行 `forgetMemberUpdateForm`。它會先關掉舊表單（LINE 裡的舊連結送出時會看到「已經停用」，不會石沉大海），再讓腳本忘記它。補送清單還有東西時會先停下來提醒；確定都不要了，改執行 `forgetMemberUpdateForm(true)`（要帶參數，照上面「要帶參數的函式怎麼執行」包一層）。**跑完一定要把「暫用」這個檔刪掉**：留著的話，日後誤選 `runOnce` 會把新的那份表單也關掉，補送清單也一起清空。
2. 執行 `createMemberUpdateForm` 建新表單，照部署表第 5、7、9 步把 `site-config.js` 的兩行換成新的。
3. 通知組長：**舊的「已帶好名字的連結」全部作廢**，要重新從成員卡複製。

> ⚠ **`INTAKE_SECRET` 外流的話，任何人都能不經過表單，直接把更新送進待審核區**（上面的自動暫停也擋不到）。要換新的時候，Cloudflare 的 Worker 變數和 Apps Script 的指令碼屬性**兩邊要一起換**，換完跑一次 `checkMemberUpdateForm`，確認「連線與密碼」是 ✅。

## 資料存放方式

**真實來源是 `data/` 資料夾**，不是根目錄的 `data.js`：

```
data/_index.json    分會結構：分組順序、代號、組名（只有總管理員能寫）
data/a1.json        A1 組的組長、招募席位、成員（A1 組長 + 總管理員能寫）
data/a2.json …      其餘 11 組
```

`data.js` 是 GitHub Action 從上面合併產生的**產出物**，給前台載入用；直接手改會在下次合併時被蓋掉。這樣拆的好處有兩個：**各組組長同時編輯互不干擾**（碰不到同一個檔），以及**權限變成路徑比對**（Worker 直接拒絕越權寫入）。

還有一個 `data/_pending.json`，放新夥伴自填表單送來、還沒被組長認領的申請。

**照片不在這個檔裡。** 未認領者的照片（尤其是名片）存在 Cloudflare R2 的**私有** bucket，`_pending.json` 只留文字與不可公開讀取的物件引用（`photoRefs`）：

```json
{ "pid": "p_xxx", "name": "申請人", "image": "", "card": "", "products": [],
  "photoRefs": { "image": { "key": "pending/p_xxx/image-<hash>.jpg",
                            "mime": "image/jpeg", "bytes": 12345, "sha256": "…" },
                 "card": null, "products": [] } }
```

這樣做的原因很直接：這個 repo 是公開的。名片上通常有手機、Email 與地址，而**還沒加入分會的人**沒有理由把那些資訊公開給全世界；更麻煩的是一旦進了 git 歷史，事後刪檔也移不掉。**認領成功的那一刻**才把 web 版照片寫進 `images/`。設定方式見 `worker/README.md` 的「4-2 綁定待認領照片的儲存空間（R2）」。

> ⚠ **超過 1MB 的檔案要用另一支 API 讀。** GitHub contents API 的 `content` 欄位只在檔案 ≤1MB 時才有內容，超過時它照樣回 200，但 `content` 是空字串。Worker 因此改成：超過就用同一個 blob sha 走 git blobs API 補讀。若哪天要新增讀取 `data/` 檔案的程式碼，請一律走 `ghReadFile()`，不要自己拆 `content` —— 一筆帶名片與商品照的申請就足以越過 1MB，而這個坑不會當場報錯，只會讓表單收不到件、組長認領一直被判「有人在你編輯期間發布過」。
>
### 待認領區能放幾筆

照片移到私有 R2 之後，「同時能有幾筆待認領」**只跟文字有關**，與照片大小完全脫鉤 —— 所以它是一個可推導的**保證**，不是估計值：

```
MAX_PENDING(30) × MAX_PENDING_ENTRY_BYTES(96 KiB) = 2.88 MiB  <  MAX_DATA_BYTES(3 MiB)
```

| | 值 | 說明 |
|---|---|---|
| **保證容量** | **30 筆**（對目前的表單 schema） | 即使每一筆的所有文字欄位都塞到 `/intake` 允許的上限、而且全是中文（UTF-8 三 bytes）、外加 7 個 `photoRefs`。**這個保證的前提是欄位上限不變** —— 加新欄位或放寬長度就要重新推導 |
| 一般資料的實際佔用 | 每筆約 1～3 KB | 真實申請不會把每個欄位都填到 400 字 |
| 第 31 筆 | `pending_full` | 明確錯誤，既有的 30 筆逐 byte 不變 |

`tests/capacity.test.mjs` 用最壞情境驗證這個保證（實測單筆 76,736 bytes < 96 KiB，30 筆共 2.20 MiB），並且會在三個常數任一個被單獨改動時直接失敗。

照片的上限則與容量無關，只跟畫質有關：

| 上限 | 值 | 位置 |
|---|---|---|
| 單張照片 | 190 KB（Apps Script 先擋） / 200 KB（Worker 以**解碼後 bytes** 為準） | `google-form.gs` / `PENDING_IMG_BYTES_MAX` |
| 每份申請張數 | 7 張（形象照 1 + 名片 1 + 商品照 5） | `PENDING_IMG_COUNT_MAX` |

**7 張都會被保存**，不會再因為「單筆總額」而被靜默丟掉其中幾張 —— 任何一張不合法時是**整筆退回**並回報是哪個欄位，而不是安靜地少一張。

**認領是伺服器端的交易**：按下「認領」會直接呼叫 Worker 的 `/claim` 並立刻寫進網站（不必再按發布）。Worker 在同一個交易裡確認該筆仍在待認領區，所以兩位組長同時認領同一人時，第二位會看到「已經被其他組長認領走了」，而不是各自建出一張成員卡。成員卡上會留下 `claimedFrom`（來源申請的 pid），這是事後唯一能判斷「這張卡從哪來」的依據。

### 有人在等的時候會被提醒

申請進了待認領區之後不會有任何人被自動通知，就這樣躺著等某位組長剛好打開後台 —— 新夥伴那頭只會覺得「送出之後就沒下文」。所以待認領區會依筆數顯示一則會升級的提醒（登入時也會跳一次）：

| 筆數 | 提醒 |
|---|---|
| 1 筆 | 不提醒 —— 清單本身就看得見，每一筆都跳會讓提醒變成被無視的雜訊 |
| **2 筆以上** | 「目前有 N 位新夥伴等待認領，請組長盡速認領組員。」 |
| 24 筆以上（上限的 80%） | 升級為警示：滿了之後新夥伴的申請**會被退回** |
| 30 筆（滿） | 申請已經在掉了，措辭是「立即認領或刪除幾筆」 |

想連信件通知也一起要，設定 `NOTIFY_EMAIL`（見上面「申請沒送成功時要有人知道」）。

### 認領前看得到照片

待認領者的照片存在**私有** R2，沒有公開網址（刻意的：還沒加入分會的人的名片不該有任何公開連結）。後台不簽網址，而是每一張都經過 Worker 的 `/pending-photo` 當場驗身分再取回內容 —— 卡片上顯示形象照縮圖，按「🔍 查看照片」可以放大看名片上的字。唯讀帳號看不到待認領區，也拿不到照片。

登出時這些預覽會立刻從瀏覽器記憶體釋放。

## 資料欄位

每個分組：`code`（代號）、`name`（名稱）、`leader`（組長）、`members`（成員陣列）。

每位成員：
| 欄位 | 說明 |
|------|------|
| `number` | 編號 |
| `name` | 姓名 |
| `title` | 行業／職稱 |
| `services` | 服務項目（一項一行） |
| `targets` | 適合引薦對象 |
| `have` | **我有…**：手上的資源、專長、人脈（一項一行） |
| `want` | **我要…**：想被引薦到的對象與需求（一項一行） |
| `tagline` | 宣傳標語 |
| `image` | 照片：檔名或內嵌圖片；空＝無照片 |
| `card` | 名片圖檔 |
| `products` | 商品／服務照片（至多 5 張） |
| `company` | 所屬公司 |
| `business_items` | 主要營業項目 |
| `website` | 公司網站 |
| `dataIssue` | `true` 時前台顯示「資料需確認」 |
| `updatedAt` | **最後更新時間**（ISO 字串，系統自動蓋章；空＝尚無紀錄） |
| `lastUpdateFrom` | 最後一次套用的夥伴資料更新編號（套用時系統自動寫入；同一筆更新靠它擋掉重複套用，手改時請保留） |

> ⚠️ **手改 `data/` 時的硬性規定**（Worker 會擋，不符合的檔案發布不上去）：
> - `id` 只能用英數字、底線與減號，最長 64 字。它會被拿去當分享頁的檔名（`m/<id>.html`），像 `../index` 這種值會蓋掉 repo 裡的其他檔案。
> - `services`、`targets`、`have`、`want`、`tagline`、`products` **一定要是陣列**（`[]` 而非 `""`）。型別錯了前台會整頁拋錯，合併腳本也會失敗。
> - 檔案必須是合法 JSON。壞掉的話同步 Action 會失敗，`data.js` 就不再更新——**整個前台會停在舊版**。

### 「我有…／我要…」

成員內頁在「服務項目／適合引薦對象」之後多出這兩個區塊，也會印在分享卡上：

- **我有**：這位夥伴手上有什麼可以給出去（資源、產能、通路、人脈、專長）。
- **我要**：希望被引薦到誰（對象、職務、產業）。

兩欄都是「一行一項」，維護方式與服務項目相同，在後台成員卡直接打。未填時前台不會顯示這兩張卡（所屬公司、主要營業項目也一樣；服務項目與適合引薦對象固定顯示、空的寫「—」），仍會被「缺資料」清單列入催收。

### 最後更新時間

任何會改到成員資料內容的動作都會自動蓋上時間戳——逐欄編輯、換照片／名片／商品照、勾選「資料需確認」都算；**單純調整排序不算**內容變更，不會蓋章。時間戳會顯示在三個地方：後台成員卡標頭（到分鐘）、前台成員內頁底部（到日）、匯出 CSV 的「最後更新」欄。後台總覽儀表板另有「近 7 天有更新」的統計。

## 設定集中處（site-config.js）

這個檔是全站設定的單一來源，分兩類：

**分會名稱與網址** — 前台首頁、分享卡、產業小組表、來賓頁與 `m/` 分享預覽頁都讀這一份，改名或搬家只要改這個檔。各頁 HTML 的 `<title>` 與 og 標籤因為要給爬蟲讀，仍是靜態文字，改名時需一併更新。

**Google 表單與試算表的連結** — 都由 `tools/google-form.gs` 的對應函式建立，執行後把「執行紀錄」印出的網址貼回這裡。**留空不會壞掉**，只是對應的按鈕不出現：

| 設定 | 用 `google-form.gs` 的 | 填了之後 |
|---|---|---|
| `VISITOR_FORM_URL` | `createVisitorForm` | `visitor.html` 的「我要報名參訪」按鈕直接開表單（未填時按鈕會改顯示「請先聯繫邀請你的夥伴」）；後台儀表板出現「來賓報名表單」捷徑 |
| `MEMBER_FORM_URL` | `createNewMemberForm` | 後台總覽儀表板出現「新夥伴填寫表單」捷徑（網址發給新夥伴，填完會出現在待認領區；Worker 要設好 `INTAKE_SECRET`） |
| `ROSTER_SHEET_URL` | `createRosterSheet` | 後台工具列與總覽儀表板出現「名冊試算表」捷徑 |
| `UPDATE_FORM_URL` | `createMemberUpdateForm` | 後台總覽儀表板出現「夥伴資料更新表單」捷徑；「缺資料清單」的催收訊息附上表單連結（見「八、夥伴資料更新表單」） |
| `UPDATE_FORM_ENTRIES` | `createMemberUpdateForm`（遺失時用 `printMemberUpdateLinkConfig` 重印） | 各題的 entry 編號，固定 11 個鍵，整段照貼。有了它，成員卡才會出現「複製已帶好名字的更新連結」，組長的催收訊息才會逐人附只預選名字的連結 |

執行方式都一樣：把 `tools/google-form.gs` 貼到 script.google.com 的專案，選那支函式按執行，看「執行紀錄」複製網址。`UPDATE_FORM_URL` 與 `UPDATE_FORM_ENTRIES` 兩行要等「八」部署表的第 7 步再貼，而且要到 GitHub 網頁版改這個檔 —— 後台的「發布」改不到它。

### 來賓在網站上直接報名（選用）

`visitor.html` 可以顯示一份 floating-label 的內嵌表單，來賓不必離開名錄網站就能報名，資料照樣進**同一張 Google 表單與來賓 CRM**。

沒設定時完全不影響現況 —— 頁面維持原本「開新分頁到 Google 表單」的按鈕。開啟方式：

1. Apps Script 執行 `printVisitorFormEntryIds()`，它會印出一段可以直接複製的設定
2. 貼進 `worker/publish-relay.js` 最上面的 `VISITOR_FORM_ID` 與 `VISITOR_ENTRY`，Deploy
3. 之後表單題目若有更動，跑 `checkVisitorEntryIds()` 核對編號有沒有跑掉

**為什麼要經過 Worker 而不是讓瀏覽器直接打 Google**：跨網域的關係瀏覽器讀不到 Google 的回應，送失敗時來賓看到的仍然是「報名成功」，單子掉了沒有人會知道。走 Worker 才拿得到真正的 HTTP 狀態；順便在那裡做 IP 限流與 honeypot，補上「自己刻表單就繞過了 Google 表單頁面本身防護」這個缺口。

> ⚠ `entry.<數字>` 是 Google 給每一題的編號，**改題目或刪掉重加會變**，而且送出時會安靜地少一欄。動過表單就跑一次 `checkVisitorEntryIds()`。

### 申請沒送成功時要有人知道（強烈建議設定）

新夥伴按下送出之後，資料要經過 Apps Script → Worker → GitHub 三段路才會出現在待認領區。任何一段失敗，**填表的人看到的仍然是 Google 的「已送出」**。

先前這種失敗只寫進 Apps Script 的「執行紀錄」就結束了 —— Apps Script 只在函式**拋例外**時才會寄失敗信給擁有者，而那段程式是正常 return，所以一封信都不會發，而執行紀錄沒有人會主動去看。結果就是申請一筆一筆掉，名錄這邊零感知。

設定收件人（用函式，不要手動加指令碼屬性 —— 名稱打錯一個字完全不會有提示）：

```js
setAlertEmail("yourname@gmail.com")     // 失敗通知，務必設
setNotifyEmail("leaders@example.com")   // 新申請與資料更新通知，選用；不要就別跑這行
```

這兩行都要帶參數，**不能直接從下拉選單選 `setAlertEmail` 按執行**（沒帶參數會把原本設好的信箱清掉）。照「八」的「要帶參數的函式怎麼執行」包一層，兩行可以一起放進 `runOnce` 的大括號裡。

| 屬性 | 作用 |
|---|---|
| `ALERT_EMAIL` | **失敗通知**。申請沒進待認領區就寄一封信，內含姓名、錯誤原因與該怎麼處理。沒設的話會退回寄給腳本擁有者 —— 但那需要「讀取你的帳號信箱」這個權限，授權沒完成時取不到，所以還是明確設一個比較好。 |
| `NOTIFY_EMAIL` | **新申請與夥伴資料更新通知**（選用）。有人進待認領區、或有夥伴從更新表單送來資料，就寄一封給組長群。不設就不寄。資料更新的成功通知 6 小時最多一封；「找不到名字」6 小時彙整一封（見「八」的「會寄哪些信」）。 |
| `VISITOR_NOTIFY_EMAIL` | **來賓報名通知**（選用）。有人在來賓頁報名就寄一封到這個信箱；沒設就依序退回 `NOTIFY_EMAIL`、`ALERT_EMAIL`、腳本擁有者。觸發器要先跑一次 `setupVisitorNotify` 裝上。 |

### ⚠ 貼上這一版之後，一定要手動執行一次任一函式重新授權

**這一步不是選用的，跳過會讓新夥伴表單整個停擺。**

通知功能用到兩個這份腳本原本沒用過的 Google 權限（寄信、讀自己的帳號信箱）。Apps Script 是靠掃描整個專案推導出需要哪些權限的，而「送出表單」那個觸發器用的是**建立當下那份授權** —— 權限集合一變大，舊授權就覆蓋不了，觸發器會以授權錯誤失敗。

失敗的樣子正好就是這整段要消滅的東西：觸發器根本沒跑，所以**連新加的失敗通知信也發不出來**；後台待認領區是空的，`/health` 也一切正常，看起來就只是「最近沒人申請」。

做法：在 Apps Script 上方的函式下拉選單選 **`checkNotifySetup`** → 按「執行」→ **看執行紀錄裡印出來的授權網址，用瀏覽器打開它**完成同意。之後再跑一次，「授權狀態」那一行會顯示 ✅；顯示紅字就代表還沒好。

> ⚠ **直接按「執行」不會跳出同意畫面。** 這支腳本把寄信相關的呼叫都包在 try/catch 裡（寄信失敗絕不能連累申請送出），而「權限不足」正是以例外的形式出現 —— 於是它被一起吞掉，函式順順跑完，編輯器也就沒有機會提示你授權。`checkNotifySetup` 因此會把 Google 給的授權網址直接印出來，那是一定走得到的路。

（`ALERT_EMAIL` 可以晚點再設，但**授權不能晚點再做** —— 沒設收件人只是退回寄給腳本擁有者，沒授權則是申請全部掉光。）

執行 `checkNotifySetup()` 同時會印出實際收件人與今日可寄額度，並**真的寄一封測試信**。「以為有設好」和「真的收得到」是兩件事，而這條路只有在出事時才會被用到。

信裡只有姓名、錯誤碼與處理建議 —— **不含照片、不含密碼、不含完整申請內容**。信會被轉寄、會留在收件匣，那不是放未認領者資料的地方。

> 常見的一種失敗：Worker 已經更新到新版，但 Cloudflare 上還沒綁 R2（`PENDING_IMAGES`）。這時 `/intake` 會把每一筆申請都退回，而後台待認領區是空的，看起來就只是「最近沒人申請」。除了這封信之外，總管理員登入後台時也會看到橫幅提示（Worker 的 `/health` 會回報 R2 綁定狀態）。

### 新夥伴照片自動歸檔（選用）

表單上傳的照片預設全部堆在 Google 自建的 `(File responses)` 資料夾裡，檔名是「題目 - 填答者」，混在一起；手動整理完，下一筆送出又會掉回去。

目的地資料夾已經寫在 `google-form.gs` 最上面的 `PHOTO_ARCHIVE_FOLDER_ID_DEFAULT`，**貼上程式碼就生效，不必再執行任何函式**。要換資料夾有兩種方式：改那個常數，或執行一次

```js
setPhotoArchiveFolder("https://drive.google.com/drive/folders/你的資料夾ID")
```

（要帶參數，做法見「八」的「要帶參數的函式怎麼執行」。指令碼屬性優先於程式碼預設值，所以換帳號或臨時改目的地時不必動程式碼。設成空字串則停用這個功能。）

每次有人送出表單，照片就會自動搬進：

```
<指定的資料夾>/新夥伴照片/<姓名>_<日期>/姓名_形象照.jpg
                                        姓名_名片.jpg
                                        姓名_商品照1.jpg …
```

- 用「移動」不是複製，不佔兩份空間；檔案 ID 不變，所以回應試算表裡那條連結照樣點得開。
- 照片會**繼承目的資料夾的分享設定** — 資料夾分享給誰，誰就看得到照片，不必一張一張開權限。
- 沒設定就整個跳過，不影響原本運作；歸檔排在送出待認領區之後並獨立包錯，**歸檔失敗不會連累新夥伴的申請**。
- 目前設定狀態（含目的地來自程式碼還是指令碼屬性）可用 `checkNewMemberSetup` 查看。

> ⚠ **這個 repo 是公開的**，資料夾 ID 任何人都讀得到。ID 本身不是密碼，能不能打開完全取決於那個資料夾的**共用設定** —— 請設成「限制」並逐一加人。若設成「知道連結的任何人」，等於把裡面的來賓電話與 LINE ID 公開給所有讀得到這個 repo 的人；權限若還是「編輯者」，別人連刪檔都做得到。

### 每月自動清掉已上線的照片（選用）

照片一旦認領發布，就變成 repo 裡 `images/` 的實體檔，Drive 那份只是中繼站。這支定時任務每月清一次 —— **純 Apps Script 的時間觸發器，跑在 Google 自己的伺服器上，不涉及任何 AI，也不需要 GitHub 權杖**。

```js
previewPhotoCleanup()        // 先試算：只列出「會刪哪些」，不動任何東西
setupPhotoCleanupTrigger()   // 確認沒問題再排定，每月 1 號凌晨執行
```

判斷「已經推上 GitHub」的依據是去讀**公開網站上的 `data.js`**：某位夥伴在名錄上、而且 `image` 欄是實體檔名（不是 `data:` 內嵌），就代表照片確實已經在 repo 裡。

刪之前要**同時**滿足三個條件，少一個就留著：

1. 資料夾建立超過 `CLEANUP_MIN_AGE_DAYS` 天（預設 30，剛送出的絕不碰）
2. 這個人不在待認領區（還沒被認領的當然不能刪）
3. 這個人在名錄上、而且有實體照片

安全設計：

- **讀不到線上資料就整批不刪**（網路問題、網址改了、格式變了、名錄是空的 —— 任一種都放棄這次清理）。「查不到」不等於「可以刪」。
- 刪除是**移到垃圾桶**不是永久刪除，30 天內都救得回來。
- 每個決定都寫進執行紀錄，看得到為什麼刪、為什麼留。

> ⚠ repo 裡那份是寬度 900 的縮圖，不是原檔。清掉 Drive 這份等於放棄原始解析度。要保留原檔就別開這個功能。
